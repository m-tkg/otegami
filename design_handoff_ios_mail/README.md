# Handoff: iOS メールアプリ — 構造整理ワイヤーフレーム

## Overview
複数アカウントを横断して使える iOS 向けメールアプリ（iOS 26+）の UI を、一貫したデザインシステムに統一するための第一段階。
バラつきの原因はビジュアルではなく「アカウント横断の置き場所」と「一覧の情報密度」が未決定なことにあるため、まず構造の選択肢を低忠実度で並べた。
このバンドルは **意思決定用のワイヤーフレーム** であり、実装仕様ではない。

差別化要素（設計上の主役）:
1. 複数アカウントの横断利用
2. 英文メールを Apple Foundation Models でオンデバイス翻訳

## About the Design Files
同梱の HTML は **HTML で作られたデザインリファレンス**（意図した構造と挙動を示すプロトタイプ）であり、そのまま製品コードにコピーするものではない。
作業は「この HTML デザインを対象コードベースの既存環境（SwiftUI 想定）で、その環境の確立されたパターンとコンポーネントを使って作り直す」こと。環境が未確立なら iOS 26+ の SwiftUI を前提に選定してよい。

## Fidelity
**Low-fidelity (lofi)。** 灰色のバー＝テキスト、破線＝区切り、水色＝アクティブ/強調のプレースホルダ。
色・タイポ・余白は確定していない。レイアウトと動線の指針としてのみ使い、スタイリングは既存のデザインシステム（後述）を適用する。

未決定（このハンドオフの目的＝ここを決めること）:
- 構造（1a / 1b / 1c のいずれか）
- 一覧レイアウト（1d / 1e / 1f）
- 操作モデル（1g / 1h / 1i の組み合わせ）

## Screens / Views

### ① 情報設計・画面フロー（排他: 1つ選ぶ）

**1a 統合受信トレイ＋アカウント絞り込みチップ**
- 目的: 全アカウントを1画面で読み、必要なときだけ絞る。
- レイアウト: 縦 flex。タイトル「すべての受信」→ 横スクロールのチップ列（全部 / 仕事 / 個人 / ＋）→ リスト → 下部タブバー3つ（メール・検索・設定）。
- 主要要素: 未読ドット（左）、件名+プレビュー2行、右端に小さくアカウント名ラベル。
- フォルダ切替はナビタイトルのタップでシート表示。階層が浅く片手完結。
- リスク: アカウントが5つ以上でチップが溢れる。

**1b 上部セグメントでアカウント切替＋左ドロワーにフォルダ**
- レイアウト: ナビ（☰ / 受信トレイ / ✎）→ セグメント（統合・仕事・個人）→ 日付見出し付きリスト → 下部ツールバー（並び替え・検索・選択）。
- リスト行: 円形アバター（26px）＋2行テキスト。日付ごとにセクションヘッダ。
- リスク: ドロワーは iOS 標準から外れる。

**1c 標準 Mail 寄り。ホーム＝メールボックス一覧**
- レイアウト: 「メールボックス」一覧 →（すべての受信 / フラグ付き / **英語のメール**（スマートボックス））→ アカウントセクション → 各行に未読数と `›`。
- 下部ツールバー: 編集 / ✎ 作成。
- 学習コストがほぼゼロ。「英語のメール」を構造に立てると翻訳という売りが露出する。
- リスク: 横断が主役なのに 1 タップ余分。

### ② 一覧レイアウト（排他: 1つ選ぶ）

**1d 標準3行＋アカウント色の左罫（3px）** — 最も無難。アバター無しで日本語の長い件名が折れにくい。密度 3/10 に合う。
**1e 言語を前に出す** — 英文行は淡い水色地＋`EN` バッジ、左罫つきで日本語要約2行、行内アクション「全文を翻訳」「原文」。詳細に入る前に読む判断ができる。リスク: 行高が不揃い、要約失敗が目立つ。
**1f 送信者グルーピング** — 1人＝1ブロック（アバター＋件数バッジ）、既読は「既読 5 ▾」でたたむ。リスク: スレッド概念と二重化。

### ③ 操作モデル

**1g スワイプ割り当て**
- 右へ短く: 既読/未読 ／ 右へ長く: アーカイブ
- 左へ: 翻訳 → 後で → 削除（削除は最も端＝ハードスワイプ必須、誤爆防止）
- 左のアクションは最大3つ。

**1h 長押し → 一括選択**
- 選択中ナビ: キャンセル / 「3件を選択中」 / 全選択。行頭に16pxチェックボックス、選択行は淡い水色地。
- 下部アクションバー: 既読に・移動・**まとめて翻訳**・削除（削除のみアクセント色）。
- 2本指ドラッグでの範囲選択も想定。

**1i 詳細画面の翻訳インタラクション**
- 件名 → 送信者行 → 翻訳バー（「英語 → 日本語（端末内で翻訳）」＋ 訳文/原文セグメント。既定は **訳文**、位置は常に固定）→ 本文。
- 段落長押しでその段落だけ原文表示。
- 下部: 「返信」＋「英語で返信を下書き」を対で置き、翻訳を読み専用機能にしない。

### ④ 残りの画面（構造が決まれば従属的に決まる）

**1j 検索** — 既定はアカウント横断。フィルタチップ（全部・添付・未読・英語）。結果は「人」「メール」でセクション分け。
**1k 作成・返信** — 最上段に「差出人: 仕事 (Google) ▾」を常時明示（複数アカウントの誤送信防止）。宛先・件名・本文・引用。下部ツールバーに 📎 と「英語に翻訳して送る」。
**1l 設定** — 3ブロック: アカウント（一覧＋追加）／操作（スワイプの割り当て）／翻訳（英文を自動で翻訳＝ON、一覧に要約を出す＝OFF）。

## Interactions & Behavior
- 遷移: 一覧 → 詳細は Push（1c は メールボックス → 一覧 → 詳細の2段）。フォルダ/アカウント切替は 1a=シート、1b=ドロワー、1c=Push。
- スワイプ: しきい値2段（短い=既読、長い=アーカイブ）。左のアクションは幅で優先度を表現。
- 長押し: 選択モードへ。ナビ/下部バーが差し替わる。
- 翻訳: オンデバイス。一覧要約は設定で OFF 既定（1e を採用する場合は ON 既定を検討）。翻訳中・失敗時の表示は未設計 → 実装時に要検討（プレースホルダ／原文フォールバック）。
- 未読/既読、フラグ、アーカイブは即時反映＋Undo（トースト）を推奨。
- ダークモード: 未設計。トークン化して両対応にすること。

## State Management
- `accounts[]`（表示名・種別・色・未読数）、`activeAccountFilter`（全部 or 特定）
- `mailbox`（受信/フラグ/英語/フォルダ）、`messages[]`（既読・フラグ・言語判定・要約キャッシュ）
- `selectionMode: Bool` + `selectedIDs: Set`
- `translationState[messageID]`: `.none | .translating | .translated(text) | .failed`、`showOriginal: Bool`
- `composeDraft`（差出人アカウントを必須フィールドとして保持）

## Design Tokens
実装のスタイリングは **Modernist デザインシステム**（フラット、角丸0、2px罫、Archivo、アクセント #ec3013）を基準にする。ただし本アプリのトーン指定は「薄い水色ベース／シンプルでスタイリッシュ／親しみやすい」。
ワイヤーフレームで使ったプレースホルダ値（**確定値ではない**）:

| 用途 | 値 |
| --- | --- |
| 背景（用紙） | `#eef3f6` |
| 面 | `#ffffff` |
| インク | `#1a1a1a` / 補助 `#666` / 薄 `#999` |
| 水色ベース（選択・強調地） | `#f4f9fc` / `#cfe4ee` / `#9fc9dd` |
| 水色アクセント（未読・リンク） | `#3d7f9e` / 文字用 `#2a6b88` |
| 破壊的操作 | `#ec3013`（Modernist accent） |
| 区切り | 主要 2px solid `#1a1a1a` ／ 行間 1px dashed `#ccc` |
| 角丸 | 0px（Modernist 準拠） |
| 余白 | 12px を基本単位（行 padding 11–13px） |
| フォント | ワイヤーは Zen Kurenaido（手書き＝lofi の合図）。実装は Archivo（英字）＋日本語は system font） |

- タップ領域は 44pt 以上を厳守。
- 本文サイズのアクセント文字色は使わず、濃いステップ（`--color-accent-700` 相当）を使う。

## Claude Code への渡し方（推奨手順）
1. このフォルダをリポジトリ直下に置く（`design_handoff_ios_mail/`）。
2. リポジトリの `CLAUDE.md` に次を追記:
   ```
   UI の設計指針は design_handoff_ios_mail/README.md を参照する。
   採用した構造: 1? / 一覧: 1? / 操作: 1g+1h+1i（決定後に記入）
   ワイヤーは lofi。レイアウトと動線のみ参照し、スタイルは既存の DesignSystem/ トークンを使う。
   ```
3. Claude Code への最初の指示例:
   > `design_handoff_ios_mail/README.md` を読んで、まず 1a の受信トレイ構造だけを既存の SwiftUI パターンで実装して。スタイルは既存トークンを使い、新しい色は追加しない。翻訳部分は差し替え可能なプロトコルで抜いておいて。
4. **1画面ずつ**依頼する（一覧 → 詳細 → 作成 → 検索 → 設定）。まとめて渡すと既存パターンから外れやすい。
5. 構造の決定（①②③の選択）は必ず先に済ませる。未決定のまま実装させると、今整理しようとしているバラつきが再生産される。
